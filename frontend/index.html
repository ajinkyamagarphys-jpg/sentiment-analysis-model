Model Training & Dataset Processing

Twitter Mental Health Dataset (Kaggle)

The BERT model was trained on a dataset of social media text specifically focused on mental health discourse. Because raw social media data is noisy, rigorous data cleaning was conducted:

  • Removed URLs, @ mentions, and special characters to isolate natural intent.
  • Converted implicit mental health categories into a structured 3-label schema (Positive, Neutral, Negative) for the local BERT component.

Training Performance (Transformer Fine-Tuning)

Using HuggingFace transformers and PyTorch via train_bert.py, the model achieved high accuracy on validation hold-outs. The loss curve demonstrated rapid convergence within the first few epochs.

System Inference Pipeline & Integration

1. FastAPI Local Model Serving

Upon training completion, the PyTorch model artifacts (weights, configurations, and tokenizers) are serialized to a local directory (model_artifacts). During system startup, FastAPI buffers the model directly into memory overhead which allows for zero-latency, local inference for base sentiment classification without relying on external cloud providers for general sentiment data.

2. Sequence of Execution (Statement Processing)

When a user submits a statement, the backend orchestrates multiple discrete systems dynamically:

  • The backend intercepts the request and fetches the most recent conversation messages from the SQLite database to provide a sliding window of localized context.
  • The local BERT model evaluates the current statement for Positive/Neutral/Negative sentiment distributions based on vector proximity calculation.
  • In parallel, the context + statement is securely formulated into a heavily constrained system prompt and pushed to the Google Gemini via REST API to map the granular mental health labels.
  • The predictions are aggregated, the newly classified message is appended to the SQLite storage, and the resulting payload is dispatched out to the frontend.

3. Lightweight Client-Side Rendering

To eliminate deployment friction, the UI is constructed entirely through pure HTML, CSS, and Vanilla JavaScript with no heavy build systems (No React/Node.js). The JavaScript frontend automatically interfaces with the local FastAPI instance across localhost domains and dynamically updates progress metrics (confidence gauges, probability distribution components, and UI styling responses).
